📚 How CampusFind AI Works

Explainable AI for college project demonstrations

Overview

CampusFind uses a multimodal AI engine to match lost and found items. The system combines multiple AI techniques to provide accurate, explainable matching results.

1. Image Analysis (Vision AI)

How It Works

When an image is uploaded, the AI analyzes it to extract:

  • Object Type: What the item is (backpack, wallet, phone, etc.)
  • Category: General category (Electronics, Bag, Wallet, etc.)
  • Colors: Primary and secondary colors
  • Brand/Logo: Visible brand names or logos
  • Features: Distinctive visual characteristics
  • Condition: Approximate condition (New, Good, Used)

AI Providers

The system supports multiple AI providers with automatic fallback:

  • OpenAI Vision API: Advanced GPT-4 Vision analysis (requires API key)
  • Local Fallback: Basic color detection and feature extraction (always available)

Privacy

Images are analyzed securely. Sensitive information detected by OCR is automatically masked.

2. Text Embeddings

What Are Embeddings?

Text embeddings convert words and sentences into numerical vectors. Similar concepts have similar vectors, even if they use different words.

Example

"Black backpack" and "Dark school bag" have similar embeddings because they represent similar concepts, even though the words are different.

How We Use It

We generate embeddings for titles, descriptions, and categories. When matching items, we calculate cosine similarity between embeddings to find semantically similar reports.

Cosine Similarity

Cosine similarity measures the angle between two vectors. Values range from 0 (no similarity) to 1 (identical). This is better than exact word matching because it understands meaning.

3. Image Embeddings

Visual Similarity

Images are converted into numerical vectors using vision models. Similar images have similar vectors, regardless of angle, lighting, or background.

Robustness

The system remains effective even when:

  • Photo angle changes
  • Lighting conditions differ
  • Background changes
  • Item is partially covered
  • Image resolution varies

Providers

  • CLIP: OpenAI's Contrastive Language-Image Pre-training model
  • OpenAI Embeddings: Text-embedding models
  • Local Fallback: Basic color histogram features

Scoring Weights

The final match score combines multiple factors with configurable weights:

  • Image Similarity: 30%
  • Text Semantics: 20%
  • Visual Attributes: 10%
  • OCR: 10%
  • Category: 10%
  • Location: 10%
  • Date/Time: 5%
  • Brand/Features: 5%

Why Multiple Factors?

No single factor is perfect. By combining multiple signals, we get more accurate and reliable matches. If one factor is weak (e.g., poor image quality), other factors can compensate.

5. Explainable AI

Why Explainability Matters

We don't just show a "95% match" score. We explain WHY the system thinks items match and what uncertainties exist.

Match Breakdown

Each match shows:

  • Overall Confidence: Final confidence score
  • Component Scores: Individual factor scores (image, text, location, etc.)
  • Evidence: What supports this match
  • Uncertainties: What makes this match uncertain
  • Explanation: Human-readable summary

Example Output

Overall confidence: 85%

Evidence:
✓ Same item category
✓ Similar visual appearance  
✓ Similar color
✓ Same campus area
✓ Reports are close in time

Uncertainties:
⚠ Brand could not be confirmed
⚠ Image angle differs

6. OCR with Privacy Protection

What is OCR?

OCR (Optical Character Recognition) extracts text from images. This can detect student IDs, phone numbers, names, and other identifying information.

Privacy Protection

Important: Sensitive information is NEVER publicly exposed.

  • OCR results are stored securely in the database
  • Public listings only show "Student ID detected" (not the actual number)
  • Sensitive data is masked: 23IT123456 → 23IT******
  • Only admins can view full OCR results

Verification Questions

OCR helps generate private verification questions without exposing sensitive data:

Instead of: "What is your student ID number?"
We ask: "What are the first two characters of your student ID?"

7. Confidence vs Similarity

Important Distinction

Similarity = How similar items appear based on raw scores

Confidence = How certain we are that this is actually a match

Why They Differ

High similarity doesn't always mean high confidence. We reduce confidence based on:

  • Missing information
  • Poor image quality
  • Generic descriptions
  • Uncertain location
  • Large time gaps

Example

Similarity: 96%
Confidence: 78%

Why lower?
- Brand uncertain
- Location approximate  
- Time difference notable

8. Human Verification Required

AI is Not Perfect

AI provides recommendations, but human verification is always required for:

  • Claim approval
  • Item handover
  • Final recovery confirmation

Human Feedback Loop

When users confirm or reject AI matches, we record this feedback. This data helps improve the system over time and provides accuracy metrics.

No Automatic Approvals

The system will NEVER automatically approve claims or release valuable items based solely on AI scores. Admins always review and approve.

9. Fallback Architecture

Three-Level Fallback

The system works even when external AI services are unavailable:

  • Level 1: Advanced external AI (OpenAI Vision, CLIP)
  • Level 2: Local ML models (sentence-transformers, basic features)
  • Level 3: Rule-based matching (text similarity, exact matches)

Automatic Fallback

If an API call fails, the system automatically falls back to the next level. Users see a message like "AI temporarily unavailable, using local matching engine."

10. Model Versioning

Tracking Models

Every AI result records:

  • Model name (e.g., gpt-4o-mini, CLIP)
  • Model version (e.g., 1.0, 2.0)
  • Analysis timestamp

Why It Matters

This allows us to:

  • Track which models perform best
  • Debug issues with specific model versions
  • Audit AI decisions
  • Roll back to previous versions if needed

11. Configuration

Environment Variables

All AI configuration is managed through environment variables in .env:

  • AI_PROVIDER: openai, local, or hybrid
  • OPENAI_API_KEY: Your OpenAI API key (optional)
  • EMBEDDING_PROVIDER: openai, local_clip, or sentence_transformers
  • OCR_PROVIDER: tesseract, openai, or easyocr
  • WEIGHT_*: Configurable matching weights

No Hardcoded Keys

API keys are never hardcoded in the application. They are loaded from environment variables, making the system secure and flexible.
